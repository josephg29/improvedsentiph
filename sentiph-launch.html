The problem, and the fix

Before

The parent spawned other Claudes to build. Free-form agents, no checks — confidently wrong code, nobody verifying. Agent soup.

The idea

Keep the orchestration. But make building deterministic: a worker builds, independent reviewers check, a fixer corrects — pure code decides the routing.

After

The parent calls build(); a pipeline runs in its own git worktree and returns a checked result. The parent stays clean and keeps orchestrating.

The principle the whole thing is built on:

Deterministic conductor, non-deterministic workers.

Recipes are data. The conductor is pure, unit-tested code — it never asks an LLM "what next?". Only the workers improvise, and their JSON output is schema-validated before it can affect routing.

How it works

you ──▶ PARENT (claude + sentiph MCP + orchestrator prompt — stays clean)
├─ spawn_terminal(task, model, effort) ──▶ plain worker (research / inspect / glue)
├─ build(task) ──▶ pipeline worker: build → check ×N → fix, in its own worktree
└─ list / read / approve / cancel — watch, then read the checked result

Recipes + a picker

quick / standard / careful. A deterministic keyword picker (not an LLM) sizes each build: risky tasks → careful, trivial → quick.

A human gate

The careful recipe pauses at awaiting_approval once the work verifies — Approve / Reject right on the node.

Isolated & durable

Each run gets its own git worktree + branch sentiph/run-N; a passed run is committed for you to merge. Survives an API restart.

Per-worker tuning

The orchestrator picks each child's model + effort — haiku for mechanical, opus for hard — and can spawn group leaders for recursive fan-out.

Schema-validated

Workers run via claude -p --json-schema; output is re-validated before routing trusts it. Completion = the process exits, never screen-scraping.

Real nodes, one canvas

Builds render as worker nodes on the same force-directed canvas as your agents — no separate tab, no overlay. The parent never leaves the orchestration layer.
