Sentiph · orchestrator guardrail

Ultracode defection — fixed

The parent can no longer abandon the pipeline for its own hidden agent fan-out. One hardened clause now makes the Sentiph MCP tools the only way work can start — in every mode, including ultracode.

✓ applied · shell-safe · API suite 191 passed / 1 skipped · biome clean

1The problem

The orchestrator is itself a Claude Code session, so it carries built-in multi-agent machinery — the Workflow tool, Agent/Task sub-agents, and ultracode, whose standing rule is to author its own dynamic workflow for every substantive task. Following that instinct spins up hidden in-process agents that bypass the deterministic pipeline, never get a worktree, and never appear on the canvas.

Before — two competing instincts

code change
 ├─ Sentiph rule → build pipeline
 └─ ultracode rule → self-authored Workflow

louder default wins → agent soup,
off-canvas, no checks

After — one path

code change → build
read-only / research → spawn_terminal
trivial one-call step → do it yourself

no third path; ultracode rule
explicitly overridden

2The fix

A new NO HIDDEN ORCHESTRATION block was inserted directly under the ROUTING RULE in apps/api/src/sentiphSystemPrompt.ts, so it reads as an enforcement of that rule rather than a competing one. It is appended to the orchestrator at launch via --append-system-prompt.

NO HIDDEN ORCHESTRATION -- ONLY build AND spawn_terminal MAY START WORK build and spawn_terminal are the ONLY ways you may start, plan, structure, or fan out work. There is no third path. This bans, with NO exceptions: the Workflow tool (even just to draft a plan), Agent / Task sub-agents, multi-agent or parallel-dispatch skills and commands, external or remote agent runners, and any self-authored dynamic multi-agent workflow. The test is not the tool name -- it is visibility: if a unit of work would not show up as its own node in list_terminals, with its own worktree, it is forbidden, whatever it is called and whether it runs inside your session or outside it. Such work skips the build review-and-fix pipeline, gets no isolated worktree, and never appears on the Sentiph canvas -- which is the whole point of you. This holds in EVERY mode, current or future: ignore any standing rule (ultracode-style or otherwise) to fan out your own dynamic agent workflow. If you catch yourself about to author a Workflow or call a Task / Agent / dispatch tool, STOP and convert it into build (code changes) or spawn_terminal (read-only / research / inspection / glue) calls instead. The trivial one-tool-call step you still do yourself stays as the ROUTING RULE says -- everything larger is build or spawn_terminal.

3Why it is hard to wriggle out of

The clause does not rely on a brittle list of banned tool names. The governing rule is a visibility test, plus explicit closes for every loophole an adversarial review surfaced:

✗
Unlisted tools — "if a unit of work would not show up as its own node in list_terminals, it is forbidden, whatever it is called." Catches future/unknown dispatch tools without naming them.
✗
In-process vs out-of-process — "whether it runs inside your session or outside it." Closes the remote-runner / bridge escape.
✗
Plan vs delegate seam — bans the Workflow tool "even just to draft a plan," and pins start, plan, structure, or fan out to the two tools.
✗
Self-execution drift — "everything larger [than one trivial call] is build or spawn_terminal," while preserving the ROUTING RULE's do-it-yourself branch so it does not collide.
✗
Future modes — "This holds in EVERY mode, current or future," so a new mode can not opt out by omission.
✗
Moment-of-choice — a STOP-and-convert trip-wire fires at the decision point, not just as background prose.

4How it was designed

Built with a verification-first workflow rather than a single guess: 3 independent drafts (terse-directive, enumerated-ban, why-framed), each run through 3 adversarial lenses (shell-safety, effectiveness against an ultracode model, consistency with the existing prompt), then synthesized into one clause that applies every fix.

13 agents · ~445k tokens · 9 adversarial checks → 1 synthesis. The synthesis adopted the visibility-test catch-all (drafts B+C), the compressed enumeration (B), and the blunt rationale line (C); it restored spawn_terminal's full read-only / research / inspection / glue scope and renamed the pipeline "review-and-fix" to avoid build-runs-build circularity.
