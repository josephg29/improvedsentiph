Recipes are data

A pipeline is a declarative list of stages — not a prompt that hopes an agent remembers the steps.

The conductor is pure code

“What happens next?” is a deterministic, unit-tested function. No LLM ever decides control flow.

Only workers improvise

Each step is a headless Claude worker whose JSON output is schema-validated before it can affect routing.

The right amount of checking — chosen for you

Leave the recipe on Auto and a deterministic, keyword-driven picker chooses — never an LLM. Or pick one yourself.

Quick

trivial tasks

build → check

One builder, one checker, no fix loop. Picked for typos, renames, docs.

Standard

default

build → check ×2 → fix

Two independent checkers gate the work; one bounded fix cycle if needed.

Careful

risky tasks

build → check ×3 → fix → approve

Three checkers and a human gate. Picked for auth, payments, migrations, secrets.

picker("Rotate the production API secret") → "careful"
picker("Fix a typo in the heading") → "quick"
picker("Add a list endpoint") → "standard"

The human gate

On a careful run, once three checkers agree the work is good, the run pauses at awaiting_approval and waits for you. Approve to pass it; reject to complete it with the issues surfaced. (Try the “Careful run” button in the demo.)

What every run gives you

Isolated

Its own git worktree on branch sentiph/run-<id>. A passed run is committed and the branch left for you to merge.

Observable

Every transition streams live to the canvas over the existing event socket. You see stages light up in real time.

Durable

One file per run on disk. Survives an API restart; an interrupted run reconciles to failed rather than hanging.

Interruptible

Cancel any in-flight run — workers are killed and the worktree cleaned up. A shared cap keeps the headless pool bounded.
